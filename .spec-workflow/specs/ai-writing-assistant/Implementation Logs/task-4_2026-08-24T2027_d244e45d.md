【一处主动重构，理由是不重构必然漂移】
`failureMessage` 原本是 `AiPanel.tsx` 里的**局部函数**。本 hook 也要用同一套错误文案映射
（unsupported-browser / 429 / http / unreachable / unknown 五分支）。
复制一份的话，将来加一个分支必然只改一处 → 两个入口对同一个错误说不同的话。
故抽成 `failure-message.ts`，`AiPanel` 改为 import。**行为零变化**，只是从一处变共用。
这属于「与当前任务直接相关」的改动，不是顺手重构。

【状态机】
`idle → running → review → idle`。**review 是必需的一态**，不能省：
流式期间文本是"静默"写进编辑器的（不进历史、不报 onChange），
**用户不点落笔它就不会被保存**——所以每个动作都必须有终态选择，
改写给「替换选区 / 插入到下方」，撰写与续写给「保留」。

【锚点选择】
改写用 `{from: range.from, to: range.to}`，撰写/续写用 `{from: head, to: head}`。
`stream-writer` 一律在 `target.to` 处流式追加，所以改写时新文本出现在**选区之后**，
落笔时才替换掉选区——用户在决定之前能同时看到原文与新文本。

【未覆盖】
本 hook 依赖 React 与真实 EditorView，本仓没有组件测试栈，故**没有单测**，
正确性靠任务 1 的事务模型单测 + 任务 12 的线上验收。这是如实记录，不是遗漏。
