## Verification

上一条日志把 G/H 列为"未验"。与其留成 `[~]` 的债，直接补验，结果 G 又抓到一个真 bug。

🔴 **Bug 3：气泡在手机宽度下溢出屏幕——而且是被单测"保护"过的那种**
390×780 模拟实测：气泡 `width: 691`、`right: 713`，**远超 390 视口**（`overflowsRight: true`）。
根因不在夹取数学，而在**我喂给它的宽度是硬编码的 `ESTIMATED_WIDTH = 360`**，真实是 691。
`bubblePosition` 的 6 条单测全绿——因为**单测用的也是我那个假设值 360**。
⇒ 这是"测试与实现共用同一个错误假设"的典型：断言再多也发现不了，
因为它验的是数学，而错的是输入。**只有真机/模拟视口能发现。**
修法：渲染后量真实 `scrollWidth`，并给气泡 `maxWidth = 视口 - 2×边距` + 横向滚动。
复验：`left: 8, right: 382, width: 374`，视口 390，两侧都不溢出，页面不横向滚动，
内部 689px 在气泡内滚动。

【顺带删掉一行不做事的代码】
修的时候在夹取里加了 `Math.min(size.width, bubbleMaxWidth(...))`，变异掉它**测试不红**。
按任务规定先分性质：查明左边界夹取已经把 `left` 压到 margin，
该 `Math.min` 在任何输入下都改变不了结果 —— **是死逻辑，不是测试缺口**。
故删代码而非补断言。真正拦溢出的是 CSS 的 `maxWidth`，
把 `bubbleMaxWidth` 变异成返回整个视口宽 → **3 条转红**，说明现在守对了地方。

⚠️ 同时修正我自己写的一条镜像断言：原先用 `Math.min(wide.width, bubbleMaxWidth(...))`
算期望值，等于把实现抄进断言，所以变异照样绿。已改为直接断言不变量。
