【按任务要求：不照搬 REST 的形状】
design 里的 `{result:{image:base64}}` 是 **REST API** 的形状。绑定 `env.AI.run` 的返回**未验**，
所以 `normalizeImageResult` 对四种都归一：`ReadableStream` / `ArrayBuffer` / `Uint8Array` /
`{image: base64}`，都不匹配则抛 502 而不是把 `undefined` 当图片写出去。
**真实走哪个分支要等任务 12 线上验完才知道**，届时如实记录——
现在写「已支持四种」是诚实的，写「已验证走 X 分支」就是撒谎。

【Content-Type 由字节定，不由上游头定】
`imageMediaType()` 读 magic bytes（PNG `89 50 4E 47` / JPEG `FF D8`），其余一律
`application/octet-stream`。依据是 design 阶段的实测：`sdxl-lightning` 的响应头写
`image/png` 而实际是 JPEG。**上游的头会说谎，字节不会。**

【空数据也拦】
`bytes.length === 0` 抛 502，避免把 0 字节"图片"传下去、进而在附件库里落一个空文件。

【限流】
提示词截断到 1000 字符；上传侧的每小时配额由既有 `POST /api/files` 承担，未重复实现。
