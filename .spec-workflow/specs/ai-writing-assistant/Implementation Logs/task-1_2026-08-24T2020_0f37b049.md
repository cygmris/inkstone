## Verification

单测 8/8 通过（headless EditorState + history()，无需 DOM）：
流式期间 undoDepth 不变 / 取消后文档与 undoDepth 与发起前逐项相同 / 落笔 undoDepth 恰好 +1 /
一次 undo 只撤 AI 段且用户之前敲的字还在 / 文档被外部改动时 commit 返回 false 且不写 /
空生成不落笔 / insert-below 与 replace-selection 的落点各自正确。

【与 design 的一处偏离，需记录】
design 写「`aiStreamUpdate` 注解定义在 `CodeEditor.tsx` 并导出」。实现改为**单独一个
`src/client/editor/ai-stream.ts`**（3 行）。理由：`stream-writer.ts` 是纯逻辑模块，
若为了拿一个常量去 import 一个 React 组件，会把整个编辑器组件树（含 i18n 与十几个 CM 包）
拖进它的依赖图，单测也跟着变重。多一个文件换取依赖方向干净。行为完全一致。

【实现细节：为什么 commit 要「先静默撤销再重插」】
流式那几十个 dispatch 都带 `addToHistory=false`，若直接留在文档里，历史里就**没有**这次生成，
`Ctrl+Z` 会越过它去撤更早的东西。先撤掉再用一次带历史的事务重插，历史里才恰好留一步。
内容相同故视觉无闪烁。

【守卫的实现选择】
`commit` 先静默撤销**再**做陈旧性比对——顺序不能反：流式期间文档里有我们插进去的字，
此时比对必然不等。撤销之后文档回到发起前，才能真实反映「有没有被外部改过」。
复用了既有 `isTargetUnchanged`，用 `WHOLE_NOTE_RANGE` 走全文比对分支。
