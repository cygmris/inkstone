## Verification

部署到 psn-note.byjs.dev（Version 5564561f）后在 Chrome 148 实测：点「Test connection」→ **12005 ms 后**给出失败文案「The request never came back. Chrome 138 and later ask for permission before a public site may reach 127.0.0.1...」，不再无限停在 Testing…。

门禁：typecheck / i18n:check / comments:check 全 PASS；vitest 全量 10 files / 112 tests passed。

根因诊断过程（重要，别把它误判成本项目的 bug）：
1. 线上点测试连接一直转圈，控制台**零报错**（无 CSP violation、无 CORS 报错）
2. 页面内直接 fetch('http://127.0.0.1:11434/v1/models') 挂到 120 秒不返回，被 CDP 超时打断
3. 对照实验：同一浏览器打开 https://convertly.zapboxapp.com 跑同一段 fetch → **同样挂住**（8 秒后被我们自己的 AbortController 中止）
   → 说明与本项目代码、CSP 配置无关
4. navigator.permissions.query({name:'local-network-access'}) 返回 state='prompt'，UA 为 Chrome/148
   → Chrome 138+ 的 Local Network Access 权限：公网 HTTPS 页面访问 loopback 需用户授权，
     待授权期间请求挂起（不是 reject）
5. 反证：本地 http://127.0.0.1:8788 页面上同一功能能拉到 5 个模型 —— loopback→loopback 不构成跨网段访问，不触发该权限

结论：CSP、CORS（OLLAMA_ORIGINS）、传输三层都已验证通过，剩下的是**浏览器权限，需要用户在 Chrome 里点一次「允许」**，自动化点不了浏览器 UI 的权限气泡。这条同样影响用户既有的 Convertly（同一台机器、同一浏览器实测复现）。
