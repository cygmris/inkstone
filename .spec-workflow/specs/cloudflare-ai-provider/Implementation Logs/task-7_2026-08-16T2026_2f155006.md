【B 项：上游 chunk 的真实形状 —— design 里唯一标了「不确定」的押注，现已实测】

绕开我们的 Worker，直接用 Global API Key 打 https://api.cloudflare.com/client/v4/accounts/<acc>/ai/run/<model>，落盘后逐行统计。真实形状是 **OpenAI chunk 形状**，且与顶层 response 字段并存：

data: {"choices":[{"delta":{"content":"","role":"assistant"},"finish_reason":null,"index":0,"logprobs":null}],"created":...,"id":"chatcmpl-...","model":"@cf/qwen/qwen3-30b-a3b-fp8","object":"chat.completion.chunk","response":"","usage":{...,"neurons":0.0647}}

三个模型实测（同一 prompt「Reply with exactly: hello world」，max_tokens=200）：
| 模型 | 总 chunk | delta.content 非空 | delta.reasoning 非空 | completion_tokens | neurons |
| qwen3-30b-a3b-fp8 | 122 | 3 | 115 | 121 | 3.75 |
| gemma-4-26b-a4b-it | 119 | 2 | 113 | 120 | 3.47 |
| gpt-oss-20b | 57 | 2 | 49 | 61 | 3.03 |

🔴 **三个模型全都输出思维链**，不是 qwen3 独有。可见输出只有 "hello world"（12 字符），却烧掉 121 个 completion token —— 约 90% 花在看不见的 reasoning 上。已据此在设置页补了一句实测得来的文案。
另：顶层 response 字段恰好只在 content 非空的那几个 chunk 上非空，两者互为镜像。
有 data: [DONE] 终止符。

【一次被我自己推翻的错误诊断，记下来免得重蹈】
线上首测 /api/ai/chat 返回 200 但 0 个内容 chunk。我第一反应是「extractDelta 先查 response，拿到空串就返回，于是每个 chunk 都被当空 delta 丢掉」——**这个诊断是错的**。真实原因是我测试时传了 max_tokens: 64，而思维链就吃掉 120 个 token，根本没轮到正文。对照实验证实：同一请求 max_tokens=64 → 0 个 content chunk；max_tokens=500 → 3 个 chunk，输出 "\n\nhello world"。
教训：形状不符与预算不够在表象上完全一样（都是「200 但没内容」），差别只能靠改变量对照跑出来。

不过 extractDelta 里那个优先级确实是个**逻辑洞**（虽然这三个模型没触发）：response 为 "" 而 delta.content 有内容时会被误丢。已改成「取两个字段里第一个非空的」，并补了三条断言与一条「忽略 reasoning 字段」的断言。
