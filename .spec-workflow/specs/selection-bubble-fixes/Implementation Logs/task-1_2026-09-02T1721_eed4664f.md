## Verification

**根因是参照系错了，不是数学错了**，所以定位前先量了线上真实坐标：

| | y |
| --- | --- |
| 视口顶 | 0 |
| **编辑器内容区顶（`.cm-scroller`）** | **80** |
| 正文首行 | 88 |

旧判据 `88 − 36(高) − 8(间隙) = 44`，而 `44 > BUBBLE_MARGIN(8)` ⇒ 判定"上方有空间" ⇒
气泡落在 y=44 —— 那里是工具栏。**该比的是内容区上边界 80，不是视口边距 8。**

改法：`bubblePosition` 加 `bounds: { top }`（默认 `BUBBLE_MARGIN`，保持既有调用与断言不变），
`measure()` 传 `scroller.top`。**没有新查 DOM**——那个矩形本来就为"选区是否滚出可视区"取过。

单测 13/13（新增 4 条）。变异验证：把 `ceiling` 换回 `BUBBLE_MARGIN` → **2 条转红**。
新断言不只验 `below` 标志，还验 `position.top >= EDITOR_TOP` 与
"上方有空间时 `top + height <= selection.top`"——即**真的没盖住选中文字**，
而不只是标志位对。另有一条验 `bounds.top` 小于视口边距时行为与默认一致（不会因为传了个小值而破坏原有夹取）。

【线上实测 A 项】全选后量矩形相交，而不是看截图：
- 气泡 `241–279`，编辑器内容区顶 `80` ⇒ `bubbleAboveContentArea: false`
- 工具栏 AI 按钮 `48–76` ⇒ `overlapsAiButton: false`
- 意外的好结果：因为翻到**整个选区之下**，实际连选中文字都没盖住
  （requirements 里预留的"压住少量选中文字可接受"这个让步**没有用上**）
