🔴 **过程中把 merge 状态毁掉过一次，值得记下来**
第一次是在探针分支上用 `git merge --no-commit` 做的。随后为了查注释白名单归属，
跑了一对 `git stash -q -u` / `git stash pop -q` —— **`git stash` 底层是 `reset --hard`，
它会清掉 `MERGE_HEAD`**，而 pop 不带 `--index`，恢复出来的全变成 unstaged。
两条命令都带 `2>/dev/null`，抱怨被吞掉，**当场完全无感**。
若就那样 `git commit`，得到的会是**单亲普通提交**：合并拓扑丢失，
下次同步会把这 13 个提交当成没合过再合一遍，而且我判断「从未同步过」用的正是
`git log --merges` 为空 —— 这条线索也会一起没掉。
判据一行：`git rev-parse -q --verify MERGE_HEAD || echo GONE`，实测输出 GONE。
处置：`git reset --hard main` 重来，改用 `git merge --no-ff` **立即提交**建立还原点，
gate 修复走后续独立提交。⇒ 教训与本会话早先那条同源：**动手前先有可提交的还原点**。
