🔴 **过程中一个纯环境问题，浪费了几轮，值得记死**
第一次开标签拿到的是**登录页**，我据此判「登录态过期」并把任务标了 `[~]` 交还给用户。
**判错了。** 用户点破后逐层查证：

1. `psn-note` 的 cookie 在 `~/.chrome-claude/Default` 里**还有 71 天有效**，不是过期
2. 跑着的 Chrome 确实是 `.chrome-claude` + `:9223`，MCP 配置也确实指向 9223
3. 决定性一步：让浏览器自己报 —— `chrome://version` 的 `profile_path` 显示
   **`/home/eason/.chrome-claude/Profile 1`**

根因：该 user-data-dir 下有 **3 个 profile**（Default=chrisyam / Profile 1=MUSA / Profile 2=eason），
启动参数没有 `--profile-directory`，**Chrome 把新标签开在"最后活跃的那个 profile 窗口"**，
恰好是 Profile 1，而它没有 Inkstone 的 cookie。

解法：`/opt/google/chrome/google-chrome --user-data-dir=/home/eason/.chrome-claude
--profile-directory=Default <url>` 拉一个 Default 窗口，新 target 即出现在同一个 :9223 上。

⚠️ 附带两次静默失败：① `nohup google-chrome ...` —— **`google-chrome` 不在该 shell 的 PATH**
（实际在 `/opt/google/chrome/`），`2>/dev/null` 把 `No such file or directory` 吞了，
我的轮询把空值当成"还没就绪"继续等；② 外部 `curl /json/list` 与 MCP `list_pages` 结果不一致，
一度让我误判 MCP 没连 9223 —— 其实只是不同 profile 窗口的 target 可见性差异。

⇒ 判据：**排查浏览器"登录态不对"时，先问浏览器自己是谁（`chrome://version` 的 profile_path），
再去查 cookie/端口/配置。** 多 profile 的 user-data-dir 下，"哪个 profile"比"哪个端口"更容易错。
